TEMPLATE EDITOR — TUTOR DOCUMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Template is a reusable question definition written in YAML.
Each time a student sees the question, random values are
substituted into it, so no two attempts are identical.

The editor has three panels:
  Left   — the YAML source you write
  Middle — the YAML with random values substituted in
  Right  — the student-facing question rendered with LaTeX

DIFFICULTY LEVELS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Each template can be assigned a difficulty level to help teachers select questions appropriate for their students’ stage of learning. Difficulty levels do not change how the template functions; instead, they describe the cognitive demand of the question.

── Easy ──────────────────────────────────────────────────
Designed to support students who are still developing confidence with the skill.

An Easy template includes additional guidance, such as:
- A formula provided in the question
- A partially completed example
- Highlighted steps
- Hints embedded in the wording

Easy questions should not have more than 3 parts.

Students who can complete Easy templates are demonstrating progress toward the syllabus expectations, with scaffolding.

── Medium ──────────────────────────────────────────────────
A Medium template assesses the skill as required by the syllabus.

Questions:
- Contain no extra hints or scaffolds
- Use standard mathematical language
- Require students to apply the skill independently

A student who can consistently complete Medium templates is performing at the expected curriculum level.

── Hard ──────────────────────────────────────────────────
Hard templates extend beyond the syllabus requirements.

These questions may involve:
- Multi‑step reasoning
- Unfamiliar contexts
- More abstract or complex variations of the skill
- Combinations of multiple concepts
- Algebraic generalisations or proofs

Hard templates are intended for enrichment, challenge tasks, or extension work.

TEMPLATE STRUCTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A template includes parameters, the question, the answer and
the solution (which is shown if an incorrect answer is provided).
The template can also include validation and diagrams.
    parameters:
        a:
          size: small
        b:
          size: small
        ans: a + b
    question:
      text: "What is {{ a }} + {{ b }}?"
      answer: "{{ ans }}"
      solution: "Add the two numbers. {{ a }} + {{ b }} = {{ ans }}"


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PARAMETERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every value that changes between attempts is declared in
the parameters block. Parameters can be referenced in the
question, answers, and solution using {{ parameter_name }}.


── Integer ──────────────────────────────────────────────────

Generates a whole number between min and max (inclusive).

  parameters:
    a:
      size: small

  size: small            # small  = 2–5
                         # medium = 2–10
                         # large  = 20–1000, rounded to 2 significant figures
                         #          e.g. 35, 80, 140, 600

  sign: pos              # pos     → always positive (default)
                         # neg     → always negative
                         # pos_neg → randomly positive or negative
  Example:
    a:
      size: small
      sign: neg          # generates -15 to -2

    b:
      size: medium
      sign: pos_neg      # generates -10 to -2 or 2 to 10

  brackets_when_negative: true
    When set, a negative value is displayed in parentheses;
    a positive value is shown as-is. e.g. -7 → (-7),  6 → 6
    Also available as a pipe: {{ n | brackets }}

If more flexibility is required use min, max and step:

  parameters:
    a:
      min: 10
      max: 100
      step: 10


── Fraction ─────────────────────────────────────────────────

Generates a proper or improper fraction, or a mixed number.

  parameters:
    a:
      type: fraction
      size: small        # small = denominator 2–5
                         # medium = denominator 2–10
                         # large  = denominator 2–20
      proper: true       # true  → numerator < denominator
                         # false → improper fraction
                         # omit  → either
      simplified: true   # default true; false allows unreduced fractions
      sign: pos          # pos (default), neg, or pos_neg (random sign)

  Mixed number (whole part + fractional part):
    a:
      type: fraction
      mixed: true
      size: small
      min_whole: 1       # minimum whole-number part (default 1)
      max_whole: 5       # maximum whole-number part (default 5)

  Fractions render automatically as LaTeX (\frac{}{}) in the
  question and solution — do NOT write \frac manually.


── Decimal ──────────────────────────────────────────────────

Generates a decimal number with a fixed number of decimal places.

  parameters:
    a:
      type: decimal
      size: small
      decimal_places: 1  # how many decimal places (default 1)

  Example output: 3.4, 7.8, 2.0 (trailing zeros stripped)

── Dollar Amount ─────────────────────────────────────────────

Generates a dollar value.

  parameters:
    price:
      type: dollar
      size: small    # whole dollars only, $3–$8
                     # medium = dollars and cents, $3.00–$10.00
                     # large  = round amounts (multiples of $10), $10–$1000

  Displays as $5, $7.45, or $200 depending on size.
  Do not combine size with min/max.


── Percentage ───────────────────────────────────────────────

Generates a percentage.

  parameters:
    rate:
      type: percent
      min: 10
      max: 90
      step: 5

  Displays as "35%".
  The % sign is added automatically. The value is stored as 0.35
  rather than 35.

  common: true
    Picks from a fixed set of commonly used percentages:
    1%, 5%, 10%, 12.5%, 20%, 25%, 50%

Note that a percentage is stored after dividing by 100. So:
 - Incorrect: principle * rate / 100
 - Correct: principle * rate

parameters:
  rate:
    type: percent
    common: true


── Choice ───────────────────────────────────────────────────

Picks one value at random from a list.

  parameters:
    angle:
      type: choice
      values: [10, 30, 45, 60, 80, 90]


── Name ─────────────────────────────────────────────────────

Picks a unique child's name at random from a built-in pool.

  parameters:
    student:
      type: name

  The pool contains 10 names (Emma, Olivia, Ava, Isabella,
  Sophia, Liam, Noah, Oliver, Elijah, James). If multiple
  name parameters are declared in the same template, each
  receives a different name automatically.

  Example:
    parameters:
      buyer:
        type: name
      seller:
        type: name
      price:
        type: dollar
        size: small

    question:
      text: "{{ buyer }} bought a book from {{ seller }} for {{ price }}."


── List ──────────────────────────────────────────────────────

Generates a list of random integers. Use for statistics questions
(mode, median, mean, range) where you need a dataset.

  parameters:
    data:
      type: list
      count: 5      # number of values in the list
      size: small   # refers to the size of each number
      # size: small   → min: 2, max: 9
      # size: medium  → min: 2, max: 20
      # size: large   → min: 2, max: 99
      order: false  # set to true to sort the list smallest to largest

Display the list in the question using a pipe:
  {{ data | sorted }}   — sorted ascending: "2, 3, 5, 7, 8"
  {{ data }}            — original (random) order: "5, 2, 8, 3, 7"
  {{ data | length }}   — number of items: "5"

List functions for use in expressions and answers:
  mode(data)      — most frequent value
  median(data)    — middle value (average of two middles if even count)
  mean(data)      — arithmetic mean
  min(data)       — smallest value
  max(data)       — largest value
  range_of(data)  — max − min
  len(data)       — count of values
  sum(data)       — total

Example — mode question:

    parameters:
        data:
          type: list
          count: 7
          size: small
        ans: {{ mode(data) }}

    validation:
    - "len([v for v in data if v == mode(data)]) >= 2"

    question:
      text: "What is the mode of {{ data | sorted }}?"
      answer: "{{ ans }}"
      solution: "**{{ mode(data) }}** appears most often. The mode is **{{ mode(data) }}**."


── Gaussian List ─────────────────────────────────────────────

Generates a list of integers drawn from a normal distribution with
a target mean and standard deviation. Use for statistics questions
that compare two datasets with different spreads.

The generated values are integers and are adjusted so the mean is
exact. Use as an expr parameter (defined after mean and sd params).

  parameters:
    mean:
      min: 10
      max: 30
      step: 5
    tight_sd:
      type: choice
      values: [1.2, 1.5, 1.8, 2.0, 2.2]
    spread_sd:
      type: choice
      values: [5.5, 6.0, 6.5, 7.0, 7.5, 8.0]
    data_a:
      expr: "gaussian_list(mean, tight_sd, 8)"
    data_b:
      expr: "gaussian_list(mean, spread_sd, 8)"

Signature:
  gaussian_list(mean, sd, count)

  mean   — target mean (integer or parameter name)
  sd     — target standard deviation (can be a decimal value)
  count  — number of values in the list

Display the list in the question:
  {{ data_a | sorted }}   — sorted ascending: "18, 19, 20, 20, 21, 22, 22, 23"
  {{ data_a }}            — original (random) order

All standard list functions work on gaussian_list results:
  mean(data_a)    median(data_a)    range_of(data_a)    etc.


── Scenario ──────────────────────────────────────────────────

Picks one or more random rows from a fixed table.

─ Single pick (default) ──────────────────────────────────────

  parameters:
    item:
      type: scenario
      rows:
        - [a soccer pitch, m]
        - [a pencil, cm]
        - [a person, m]
        - [a tower, m]
        - [a staple, cm]
        - [a fingernail, mm]
        - [a marathon route, km]
    question_text: item[0]
    unit: item[1]

Access fields by index inside {{ }}:
  {{ item[0] }}   — first field
  {{ item[1] }}   — second field
  {{ item[2] }}   — third field (if the row has a third value), etc.

  question:
    text: "Which unit (m, cm, mm, km) is most appropriate to measure {{ question_text }}?"
    answers:
      - text: m
        correct: "unit == 'm'"
      - text: cm
        correct: "unit == 'cm'"
      - text: mm
        correct: "unit == 'mm'"
      - text: km
        correct: "unit == 'km'"
    solution: "The most appropriate unit to measure {{ question_text }} is {{ unit }}."

─ Multiple picks — count: N ──────────────────────────────────

Add count: N to pick N rows from the same table. By default the
picks are distinct (no repeated row). Set allow_repeats: true to
allow the same row to appear more than once.

When count > 1 the value is a list of lists. Access each pick
with double indexing: activity[pick_index][field_index].

  parameters:
    activity:
      type: scenario
      count: 2            # pick two distinct rows
      rows:
        - ["Sport",      "plays sport",            "play sport",            "Plays Sport"]
        - ["Gaming",     "plays video games",       "play video games",      "Plays Video Games"]
        - ["Cycling",    "cycles to work",          "cycle to work",         "Cycles to Work"]
        - ["Bilingual",  "speaks another language", "speak another language","Speaks Another Language"]
        - ["Swimming",   "swims competitively",     "swim competitively",    "Swims Competitively"]

  Access:
    {{ activity[0][0] }}  — label of first pick     e.g. "Sport"
    {{ activity[0][1] }}  — verb phrase of first pick (3rd person)
    {{ activity[0][2] }}  — verb phrase of first pick (infinitive)
    {{ activity[0][3] }}  — display label of first pick
    {{ activity[1][0] }}  — label of second pick    e.g. "Gaming"
    {{ activity[1][3] }}  — display label of second pick

  Example question using two picks:
    text: >
      In a survey of 100 people, {{ both }} {{ activity[0][1] }} and
      {{ activity[1][1] }}. {{ a_only }} {{ activity[0][1] }} but do not
      {{ activity[1][2] }}.

  allow_repeats: true — allow the same row to be picked more than once:
    activity:
      type: scenario
      count: 2
      allow_repeats: true
      rows: [...]

Rules:
  • Each row must have the same number of fields.
  • Row values can be strings, numbers, or a mix.
  • count: 2 requires at least 2 rows (unless allow_repeats: true).


── Derived (expr) ────────────────────────────────────────────

Computes a value from an expression over other parameters.
Use this to name an intermediate result so you can reference it
cleanly in the question, solution and answers without repeating
the full expression each time.

  parameters:
    a:
      size: small
    b:
      size: small
    perimeter: 2 * (a + b)
    area: a * b"

  question:
    text: "A rectangle has length {{ a }} and width {{ b }}. What is its perimeter?"
    answer: "{{ perimeter }}"
    answer_format: integer
    solution: "Perimeter = 2 × ({{ a }} + {{ b }}) = {{ perimeter }}"

Rules:
  • The expr parameter must be defined after any parameters it
    references (definition order is top-to-bottom).
  • The {{ and "" wrappers are optional — each form works:
      perimeter: 2 * (a + b)
      perimeter: "2 * (a + b)"
      perimeter: "{{ 2 * (a + b) }}"
  • Derived parameters can reference other derived parameters as
    long as they appear in the calculated order.
  • The value is available in {{ }}, answers, solution, and
    validation rules just like any other parameter.


── Fixed Value ───────────────────────────────────────────────

Sets a parameter to a fixed constant (no randomisation).

  parameters:
    total_cards:
      value: 52
    diamond_cards:
      value: 13

  Useful when a question has a known constant (e.g. a deck of
  cards, number of days in a week) that you want to reference
  by name in expressions rather than hard-coding the number.


── Bool ──────────────────────────────────────────────────────

Randomly generates true or false (50/50 by default). Use this
when a question has two distinct cases — for example, whether
an angle is a right angle, or whether a number is even.

  parameters:
    right_angle:
      type: bool

  Optional weight: controls the probability of true (0.0–1.0, default 0.5):
    is_direct:
      type: bool
      weight: 0.3    # true 30% of the time

  With expr: evaluates a condition instead of picking randomly.
  Supports ^ for exponentiation and = for equality:
    right_angle:
      type: bool
      expr: "a ^ 2 + b ^ 2 = c ^ 2"

Full example

    parameters:
      right_angle:
        type: bool

    question:
      text: "Is a triangle {{ 'with' if right_angle else 'without'}} a 90° angle a right-angle triangle?"
      answers:
        - text: "Yes"
          correct: "right_angle"
        - text: "No"
          correct: "not right_angle"
      solution: "A triangle {{ 'with' if right_angle else 'without'}} a 90° angle is {{ '' if right_angle else 'not '}}a right-angle triangle."

EXPRESSIONS  {{ }}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Any text enclosed in {{ }} is evaluated as a mathematical
expression using the current parameter values.

  {{ a }}           — renders the value of parameter a
  {{ a + b }}       — evaluates a + b
  {{ a * b }}       — evaluates a × b
  {{ a / b }}       — evaluates a ÷ b (as a fraction if needed)
  {{ a ** 2 }}      — evaluates a²
  {{ rate / 100 }}  — converts a percentage to a decimal

Expressions can appear in question text, solution text, and
answer expressions.

── Built-in Math Functions ──────────────────────────────────

Standard mathematical functions can be used directly inside
{{ }} expressions:

  {{ a ** 2 }}          — a squared
  {{ a ** 0.5 }}        — square root of a (also sqrt(a))
  {{ sqrt(a) }}         — square root
  {{ abs(a - b) }}      — absolute value
  {{ factorial(n) }}    — n!  (e.g. factorial(5) = 120)
  {{ sin(a) }}          — sine (angle in radians)
  {{ cos(a) }}          — cosine (angle in radians)
  {{ tan(a) }}          — tangent (angle in radians)
  {{ asin(a) }}         — inverse sine; result in radians
  {{ acos(a) }}         — inverse cosine; result in radians
  {{ atan(a) }}         — inverse tangent; result in radians
  {{ log(a) }}          — natural logarithm (ln)
  {{ log(a, b) }}       — logarithm base b of a  (e.g. log(8, 2) = 3)
  {{ log10(a) }}        — base-10 logarithm
  {{ degrees(a) }}      — convert radians to degrees
  {{ radians(a) }}      — convert degrees to radians
  {{ ceil(a) }}         — round up to nearest integer
  {{ floor(a) }}        — round down to nearest integer


── Surd Functions ───────────────────────────────────────────

These functions simplify square roots into surd form and are
used together with the | surd format pipe.

  {{ sqrt(n) | surd }}
    Renders the simplified surd form of √n.
    e.g. n=12 → 2\sqrt{3},  n=8 → 2\sqrt{2},  n=16 → 4

  {{ surd_coeff(n) }}
    Returns the integer coefficient extracted from √n.
    e.g. surd_coeff(12) = 2  (because √12 = 2√3)

  {{ surd_radicand(n) }}
    Returns the remaining radicand after simplification.
    e.g. surd_radicand(12) = 3  (because √12 = 2√3)

Use surd_coeff and surd_radicand to construct distractor
answers for surd simplification questions:

  parameters:
    n:
      type: choice
      values: [8, 12, 18, 20, 27, 32, 45, 50, 72, 75]

  question:
    text: "Express $\\sqrt{{{ n }}}$ in simplified form."
    answers:
      - text: "${{ sqrt(n) | surd }}$"
        correct: true
      - text: "$\\sqrt{{{ n }}}$"
        correct: false
      - text: "${{ surd_coeff(n) }}$"
        correct: false
      - text: "${{ surd_coeff(n) ** 2 }}\\sqrt{{{ surd_radicand(n) }}}$"
        correct: false

  The three distractors represent common mistakes:
    $\sqrt{n}$          — not simplified at all
    $a$                 — forgot the remaining radical
    $a²\sqrt{b}$        — used the square of the coefficient


── Fraction Part Functions ──────────────────────────────────

Extract the numerator or denominator of a fraction parameter:

  {{ denominator(a) }}  — the denominator of fraction a
                          e.g. if a = 3/4, returns 4
  {{ numerator(a) }}    — the numerator of fraction a
                          e.g. if a = 3/4, returns 3

These are useful when you need to refer to the parts of a
fraction separately in a question or solution:

  question:
    text: "Write a fraction with denominator {{ denominator(a) }}
           that is equivalent to {{ a }}."
    solution: "Multiply both parts by {{ denominator(a) }}:
               {{ numerator(a) }} / {{ denominator(a) }} = {{ a }}"

Also useful in answer expressions:
  question:
    text: "..."
    answers:
      - text: "{{ a * 12 / denominator(a) }}"
        format: fraction
        correct: true


── Number Theory Functions ───────────────────────────────────

  {{ gcd(a, b) }}              — greatest common divisor of a and b
                                 e.g. gcd(12, 8) → 4
  {{ lcm(a, b) }}              — least common multiple of a and b
                                 e.g. lcm(4, 6) → 12
  {{ factors(n) }}             — all factors of n, comma-separated
                                 e.g. factors(10) → '1, 2, 5, 10'
                                 (for prime factorisation use {{ n | factor }})
  {{ simplified_ratio(a, b) }} — ratio a:b reduced to lowest terms
                                 e.g. simplified_ratio(4, 8) → '1:2'

These are particularly useful in fraction and ratio questions:

  gcd_ans:
    expr: "gcd(abs(a_ans), lcd)"

── Repeat Function ──────────────────────────────────────────

repeat(value, count, separator) repeats a value count times,
joined by separator. Useful for expanded index-notation questions.

  repeat(A, n, ' × ')
    Repeats A, n times, separated by ' × '.
    e.g. A='a', n=4  →  a × a × a × a

Example — index notation:

  parameters:
    A:
      type: choice
      values: [a, b, x, y]
    n:
      type: int
      min: 2
      max: 5

  question:
    text: "Write in index notation: {{ repeat(A, n, ' × ') }}"
    parts:
      - text: "Write {{ repeat(A, n, ' × ') }} in index notation."
        answer: "{{ A }}^{{ n }}"

The separator can be anything — use ' × ' for a multiplication
symbol, ' \\times ' for LaTeX, or '' (empty string) for no gap.

── Probability Functions ────────────────────────────────────

These functions are available for probability and combinatorics
questions:

  nCr(n, r)
    Combinations — the number of ways to choose r items from n
    without regard to order.
    Formula: n! / (r! × (n-r)!)
    Example: {{ nCr(n, r) }}  → "How many ways can {{ r }} students
             be chosen from a class of {{ n }}?"

  nPr(n, r)
    Permutations — the number of ways to arrange r items chosen
    from n where order matters.
    Formula: n! / (n-r)!
    Example: {{ nPr(n, r) }}  → "How many 3-digit codes can be
             formed from {{ n }} different digits?"

  ways_sum(dice, target)
    Counts how many outcomes of rolling a given number of standard
    6-sided dice produce a specific total.
    Example: {{ ways_sum(2, 7) }} → number of ways two dice sum to 7
    Use with a choice parameter for the target:
      target:
        type: choice
        values: [5, 6, 7, 8, 9]

  hypergeom(N, K, n, k)
    Hypergeometric probability — the probability of drawing exactly
    k "successes" when drawing n items without replacement from a
    population of N that contains K successes.
    N = population size
    K = number of successes in population
    n = number of draws
    k = desired number of successes
    Example: {{ hypergeom(10, 4, 3, 2) }} → probability that exactly
             2 of 3 drawn items are defective, from a batch of 10
             containing 4 defective items.

Probability function examples in a full answer expression:
  question:
    text: "How many ways can {{ r }} items be chosen from {{ n }}?"
    answers:
      - text: "{{ nCr(n, r) }}"
        correct: true
      - text: "{{ nPr(n, r) }}"
        correct: false
      - text: "{{ nCr(n, r) * 2 }}"
        correct: false
      - text: "{{ nCr(n-1, r) }}"
        correct: false


── Unit Conversion ──────────────────────────────────────────

unit_multiplier(input_prefix, output_prefix)
  Returns the multiplier M such that:
    quantity_in_input_unit × M = quantity_in_output_unit

  Both arguments are SI prefix strings (see table below).
  Use '' (empty string) for the base unit (metres, grams, etc.).
  Returns an integer when M ≥ 1, otherwise a decimal.

  Examples:
    {{ unit_multiplier('k', 'c') }}   → 100000  (1 km = 100 000 cm)
    {{ unit_multiplier('k', '')  }}   → 1000    (1 km = 1 000 m)
    {{ unit_multiplier('',  'c') }}   → 100     (1 m  = 100 cm)
    {{ unit_multiplier('c', 'k') }}   → 0.00001 (1 cm = 0.00001 km)
    {{ unit_multiplier('M', 'k') }}   → 1000    (1 Mm = 1 000 km)

  Supported prefixes:
    'T'   tera   ×10¹²
    'G'   giga   ×10⁹
    'M'   mega   ×10⁶
    'k'   kilo   ×10³
    'h'   hecto  ×10²
    'da'  deca   ×10¹
    ''    (base) ×10⁰
    'd'   deci   ×10⁻¹
    'c'   centi  ×10⁻²
    'm'   milli  ×10⁻³
    'u'   micro  ×10⁻⁶  (also 'μ')
    'n'   nano   ×10⁻⁹
    'p'   pico   ×10⁻¹²

  Typical template pattern — randomise the input prefix and ask
  the student to convert to a fixed output unit:

    parameters:
      from_prefix:
        type: choice
        values: ["k", "c", "m"]
      value:
        min: 1
        max: 20

    question:
      text: "Convert ${{ value }}$ {{ from_prefix }}m to centimetres."
      answer: "{{ value * unit_multiplier(from_prefix, 'c') }}"


── Algebraic Expressions ────────────────────────────────────

When an answer contains a variable letter (like x or y),
collect all like terms into a single {{ }} coefficient:

  WRONG:  "{{ 2 * a }}x + {{ 2 * b }}x"    ← two x-terms
  RIGHT:  "{{ 2 * a + 2 * b }}x"            ← combined

Write in standard form: highest degree first, constant last.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
VALIDATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

If there are some combinations of parameter values that should
be ignored, these can be rejected using validation.

  validation:
      - m != 0
      - a + b > 0
      - a != b
      - len([v for v in data if v == mode(data)]) >= 2

Rules use standard Python comparison operators:
  !=  not equal
  ==  equal
  >   greater than
  <   less than
  >=  greater than or equal
  <=  less than or equal


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The question block is a single text field. Use {{ }} for
parameter references and calculations.

  question: What is {{ a }} + {{ b }}?

── Highlighting ─────────────────────────────────────────────

Use ** before and after text you would like to highlight.

  question: What is **{{ a }} + {{ b }}**?

── Indentation ──────────────────────────────────────────────

Use \quad (or \qquad for more space) inside math mode to indent.

  question: "Solve the equation:\n\n  $\\quad x^2 + {{ p }}x + {{ q }} = 0$"

── Format Pipes ─────────────────────────────────────────────

If a value is defined with a type it will be formatted based on that type.
To adjust default formatting or to format an expression (expressions don't have types)
use pipes.

  {{ expr | fraction }}                     — displays as a fraction
  {{ expr | mixed_number }}                 — displays as a mixed number
  {{ expr | decimal }}                      — displays as a decimal (fixed 2 decimal places by default)
  {{ expr | decimal(decimal_places=1) }}    — fixed 1 dp, e.g. 7.5, 6.0
  {{ expr | decimal_0 }}                   — 0 decimal places, e.g. 8
  {{ expr | decimal_1 }}                   — 1 decimal place, e.g. 7.5
  {{ expr | decimal_2 }}                   — 2 decimal places, e.g. 7.50
  {{ expr | decimal_3 }}                   — 3 decimal places, e.g. 7.500
  {{ expr | dollar }}                       — displays as $X.XX
  {{ expr | percent }}                      — displays as X%
  {{ expr | percent(decimal_places=1) }}    — fixed 1 dp, e.g. 33.3%
  {{ expr | integer }}                      — rounds to nearest whole number
  {{ expr | words }}                        — spells the integer out in English
  {{ expr | factor }}                       — prime factorisation, e.g. 12 → 2 x 2 x 3
  {{ expr | scientific_notation }}          — scientific notation, e.g. 3200 → 3.2 × 10³
  {{ expr | scientific_notation(sig_figs=2) }} — control significant figures (default 3)
  {{ expr | expr }}                         — formats an algebraic expression string for display:
                                              removes * (2*x → 2x), converts ** to ^,
                                              collapses sign pairs (+ - → -, - - → +)
                                              ^ is rendered as a superscript by the Latex component
                                              and by the AlgebraTable diagram label.
  {{ expr | pronumeral }}                   — formats a coefficient for use before a variable:
                                              1 → '' (nothing), -1 → '-', 0 → '', n → n
                                              e.g. {{ a | pronumeral }}x renders as x, 2x, -x
  {{ expr | comma }}                        — adds thousand separators: 1234567 → 1,234,567
  {{ expr | ratio }}                        — converts a fraction or float to ratio notation:
                                              5/2 → '5:2',  2.5 → '5:2'
  {{ expr | simplified_ratio }}             — simplifies a ratio string to lowest terms:
                                              '4:8' → '1:2',  '6:9' → '2:3'
  {{ expr | simplified }}                   — algebraically simplifies a math or LaTeX expression
                                              and returns a student-typeable string.
                                              Accepts plain math or LaTeX (\dfrac, \times, \div).
                                              Pure-numeric result: fraction notation, e.g. '3/14'.
                                              Symbolic result: typed notation, e.g. '3x^2/20'.
                                              Default variable: x. Override with simplified(var=t).
                                              e.g. {{ question | simplified }} where question is
                                              '\dfrac{ 3x }{ 7 } \times \dfrac{ 4x }{ 2 }'  →  '6x^2/7'
  {{ expr | operation }}                    — typesets operator symbols: * → ×, / → ÷
  {{ expr | lower }}                        — converts a string to lowercase: 'Run' → 'run'
  {{ expr | capitalize }}                   — capitalises the first letter: 'run' → 'Run'
  {{ list | length }}                       — number of items in a list: [[1,45],[2,55],[3,62]] → 3

  Example:
    parameters:
      expr_string:
        expr: "{{ m }}*x^2 + {{ b }}"

    question:
      text: "Evaluate {{ expr_string | expr }} for the given values of x."
      diagram: AlgebraTable(x_min: 1, x_max: 6, expr: "{{ expr_string | expr }}")

  With m=2, b=-4 this produces the label "2x^2 - 4" with the 2 rendered as a superscript.

── Multi-part questions ─────────────────────────────────────────────

A multi-part question asks the student several questions in sequence. Each part has
its own question text, accepted answer, and solution explanation. Each part has:
  text              — the question text for this part (supports {{ }})
  answer            — the accepted answer (supports {{ }} expressions)
  solution          — shown after the student answers (supports {{ }})
  choices           — (optional) list of multiple-choice options (see below)
  tolerance         — (optional) numeric tolerance for answer matching
  format_instruction — (optional) hint shown below the input box

  question:
    text: "Use the graph to answer the questions below."
    parts:
      - text: "Which month has the highest temperature?"
        answer: "July"
        solution: "July is the peak of the graph."
      - text: "Which month has the lowest temperature?"
        answer: "January"
        solution: "January is the lowest point."
      - text: "What is the drop from July to August?"
        answer: "{{ jul - aug }}"
        solution: "The temperature drops from {{ jul }} to {{ aug }},
                   a fall of {{ jul - aug }}°C."

── Multiple-choice parts ─────────────────────────────────────

If you need a multiple choice answer as part of the multi-part question
replace the answer with choices:

  parts:
    - text: "Is {{ a }} a terminating decimal?"
      choices:
        - text: "Yes"
          correct: true
        - text: "No"
          correct: false
      solution: "{{ a }} terminates because its denominator has
                 only factors of 2 and 5."


── Example: Multiple Part Multiple Choice question────────────

  parameters:
    a:
      type: fraction
      size: small
      proper: true
    is_term:
      expr: denominator(a) % 2 == 0 or denominator(a) % 5 == 0
    ans:
      expr: '"Yes" if is_term else "No"'

  question:
    text: "Consider the fraction {{ a | fraction }}."
    parts:
      - text: "Write {{ a | fraction }} as a decimal."
        answer: "{{ a | decimal }}"
        solution: "{{ a | fraction }} = {{ a | decimal }}"
      - text: "Is {{ a | fraction }} a terminating decimal?"
        choices:
          - text: "Yes"
            correct: is_term
          - text: "No"
            correct: not is_term
        solution: "{{ ans }}, because the denominator
                   {{ 'has' if is_term else 'does not have' }}
                   only factors of 2 and 5."


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Answer keys use the same flat structure whether the question is
single-part or a part inside a multi-part question. The keys
sit alongside the question text at the same level:

  question:
    text: "What is {{ a }} + {{ b }}?"
    answer: "{{ a + b }}"
    answer_format: integer
    tolerance: 0.5
    format_instruction: "Enter a whole number"
    solution: "{{ a }} + {{ b }} = {{ a + b }}"

The same keys work identically inside a parts: item:

  question:
    text: "Consider the numbers {{ a }} and {{ b }}."
    parts:
      - text: "What is their sum?"
        answer: "{{ a + b }}"
        answer_format: integer
        solution: "{{ a }} + {{ b }} = {{ a + b }}"

── answer ───────────────────────────────────────────────────

  answer: "{{ a + b }}"

The expression is evaluated and the student's response is
compared to it. Comparison is case-insensitive and trims
whitespace. Numeric answers are compared with a small
tolerance so that e.g. "10.0" matches "10".

── answer_format ────────────────────────────────────────────

If an answer must be provided in a particular format use
answer_format. If an incorrect format is submitted an error
is shown but the attempt is not counted as incorrect.

  answer_format: fraction            — input must be an improper fraction n/d
                                       (e.g. 7/3). Mixed numbers like "2 1/3"
                                       are rejected, so students must convert.
  answer_format: integer             — input must be a whole number
  answer_format: decimal             — input must be a decimal number
  answer_format: ratio               — input must contain :  (e.g. 1:2)
  answer_format: scientific_notation — input must be in scientific notation,
                                       e.g. 3.2 × 10³ or 3.2e3. The answer
                                       is compared numerically so the student
                                       can type any equivalent form.
  answer_format: equation            — replaces the text box with a custom
                                       base^exponent input widget. The value
                                       is stored as "base^exp" (e.g. "5^2")
                                       and compared numerically to the correct
                                       answer (25).
  answer_format: log                 — student types their answer in a single text
                                       box as log_2(10). As they type, a live
                                       KaTeX preview appears below ("Your answer:
                                       log₂(10)") so they can verify the engine
                                       has interpreted the base and argument
                                       correctly. The answer is compared
                                       numerically to the correct answer. The
                                       correct answer is typically set with
                                       log(arg, base), e.g.:
                                         expr: "log(b, a)"  # log_a(b)

Example — fraction to decimal conversion:

  parameters:
    a: { type: fraction, size: small, proper: true }
  question:
    text: "What is {{ a | fraction }} as a decimal?"
    answer: "{{ a | decimal }}"
    answer_format: decimal
    solution: "{{ a | fraction }} = {{ a | decimal }}"

── tolerance ────────────────────────────────────────────────

For answers where an exact match is not required:

  question:
    text: "What is 1/3 as a decimal to 2 d.p.?"
    answer: "{{ 1/3 | decimal(decimal_places=2) }}"
    tolerance: 0.005

Any response within ± tolerance of the correct answer is
marked correct.

── format_instruction ───────────────────────────────────────

When answer_format is set, a default instruction is shown to
the student (e.g. "Enter as a fraction, e.g. 7/3"). Override
it with:

  question:
    text: "..."
    answer: "{{ a * b }}"
    format_instruction: "Enter a whole number, e.g. 42"

── Multiple Choice ───────────────────────────────────────────

Use answers: with a list of {text, correct} dicts. The text is
shown on each button and supports {{ }} expressions and
conditional text. correct may be a boolean or an expression.

  question:
    text: "What is {{ a }} × {{ b }}?"
    answers:
      - text: "{{ a * b }}"
        correct: true
      - text: "{{ a + b }}"
        correct: false
      - text: "{{ a * b * 2 }}"
        correct: false
      - text: "{{ a - b }}"
        correct: false

The format: key applies a pipe formatter to the text value:

  answers:
    - text: "{{ a * b }}"
      format: fraction
      correct: true

── Multiple Choice Diagrams ──────────────────────────────────

For questions where the answer IS a diagram (e.g. "which graph
shows…?"), use a diagram key inside each answer item:

  question:
    text: "Which graph shows y = {{ m }}x + {{ b }}?"
    answers:
      - diagram: "Cartesian(xmin: -6, xmax: 6, ymin: -6, ymax: 6, eq: \"{{ m }}*x + {{ b }}\")"
        correct: true
      - diagram: "Cartesian(xmin: -6, xmax: 6, ymin: -6, ymax: 6, eq: \"{{ -m }}*x + {{ b }}\")"
        correct: false

The correct key supports expressions evaluated against parameters:

      correct: rel_type == "linear"

── Multiple Answers ──────────────────────────────────────────

When a question has more than one answer (e.g. two roots), use
answers: with a list of {answer:, label:} dicts. The student
gets one input box per item.

  question:
    text: "Solve ${{ a }}x^2 + {{ b }}x + {{ c }} = 0$"
    answers:
      - answer: "{{ r1 }}"
        label: "x₁"
      - answer: "{{ r2 }}"
        label: "x₂"

This renders as:   x₁ = [    ]   x₂ = [    ]   [Submit]

Labeled inputs are matched positionally. Omit label: for
order-insensitive matching (student may enter values in any
order).

Each item can carry its own answer_format and tolerance,
overriding any question-level default:

  question:
    text: "Find the gradient and y-intercept."
    answer_format: fraction        # default for both inputs
    answers:
      - answer: "{{ m }}"
        label: "Gradient"
      - answer: "{{ b }}"
        label: "y-intercept"
        answer_format: integer     # override for this input only

The same structure works inside a parts: item:

  parts:
    - text: "Find both x-intercepts."
      answers:
        - answer: "{{ r1 }}"
          label: "x₁"
        - answer: "{{ r2 }}"
          label: "x₂"

Legacy syntax (still supported):

  answer:
    multiple_answers: [r1, r2]              # unlabelled

  answer:
    multiple_answers:                       # labelled
      - x: x0
      - y: y0

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
SOLUTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The solution appears when an incorrect answer is provided.
It can provide some insight into how to answer the question,
although this is often left to the tutor.

  question:
    text: "..."
    solution: "The answer is: {{ answer }}"

Providing a solution to a question is optional. In the case
where a solution is not provided, a simple default solution
that shows the answer is provided.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
CONDITIONAL TEXT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Python ternary pattern works inside any {{ }} expression.
Use it when wording is conditional.

Syntax:
  {{ 'text if true' if condition else 'text if false' }}

Condition can be any Python expression:
  if some_bool              — bool parameter
  if x == 'value'           — choice parameter equality
  if x == 'a' else ... else — chained choices (see below)
  if n > 10                 — numeric comparison
  if n % 2 == 0             — any expression

Chaining for choice parameters:

  When a choice parameter has more than two values, chain the
  ternary to cover each case:

  {{
      'A segment' if type == 'Segment' else
      'A ray' if type == 'Ray' else
      'A line'
  }}

  This is equivalent to:
    if type == 'Segment' → 'A segment'
    elif type == 'Ray'   → 'A ray'
    else                 → 'A line'

Conditional solution example (choice parameter):

  parameters:
    type:
      type: choice
      values: ['Segment', 'Ray', 'Line']

  question:
    text: "What is this figure called?"
    solution: >
      {{ 'An interval (or segment) has two endpoints and
      does not extend.' if type == 'Segment' else
      'A ray has one endpoint and extends infinitely in
      one direction.' if type == 'Ray' else
      'A line extends infinitely in both directions.' }}

Conditional mid-sentence:

  question:
    text: "..."
    solution: "The figure is {{ 'bounded at both ends' if type == 'Segment' else 'bounded at one end' if type == 'Ray' else 'unbounded' }}."

Numeric condition example:

  parameters:
    n: { size: small }

  question:
    text: "..."
    solution: "{{ n }} is {{ 'even' if n % 2 == 0 else 'odd' }}."

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DIAGRAMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

To include a diagram, add 'diagram:' and the required diagram.

── Angle Diagram ────────────────────────────────────────────

Draws rays from a vertex with arcs and labels for one or more
named angle segments.

Syntax:

  diagram: 'Angle(A: 40)'
  diagram: 'Angle(A: 30, B: 90, C: 20)'
  diagram: 'Angle(A: 40, size: 180)'
  diagram: 'Angle(A: 30, B: 60, label_A: "x", label_B: "2x", arc_B: 2)'
  diagram: 'Angle(A: {{ a }}, B: {{ b }}, C: {{ c }}, arc_B: 2, arc_C: 3, labels: false)'

Parameters:

  A / B / C …   Named angle segments in degrees (any uppercase letter).
                Multiple angles are laid out consecutively from 0°.
                Boundary rays are drawn at 0°, between each segment,
                and at the end of the last named segment.

  size          Total extent of the diagram. Must be 90, 180, or 360.
                  size: 90   — draws a right-angle context (quarter turn)
                  size: 180  — draws a straight-line context (half turn)
                  size: 360  — draws a full revolution (no closing ray)
                If omitted, the diagram extent equals the sum of the
                named angles (just the angles, no extra space).
                When size > sum of named angles, an extra unlabelled
                region fills the remainder.

  label_X       Override the display label for angle X.
                Default label is the numeric value with a ° symbol.
                Set to "" to hide the label entirely.
                  label_A: "x"         — shows "x" instead of "40°"
                  label_A: "{{ a }}°"  — dynamic label from a parameter
                  label_A: ""          — hides the label

  arcs_X / arc_X  Number of concentric arcs drawn for angle X (default 1).
                Use different arc counts to distinguish angles in a diagram.
                Both arc_X and arcs_X are accepted.
                  arc_A: 1   — single arc (default)
                  arc_B: 2   — double arc
                  arc_C: 3   — triple arc

  labels        Set to false to hide all angle labels globally.
                  labels: false   — no labels drawn for any angle
                  labels: true    — default, labels shown
                Individual label_X overrides still apply when labels: true.

Legacy syntax:

  diagram: 'Angle(deg: {{ angle }})'   — single unnamed angle, still supported

Examples:

  Single angle — "Estimate the size of the angle shown":

    parameters:
      angle:
        type: choice
        values: [10, 30, 45, 60, 80, 90, 120, 135, 150]

    diagram: 'Angle(A: {{ angle }})'

    question:
      text: "Estimate the size of the angle shown."
      answers:
        - text: "{{ angle }}°"
          correct: true
        - text: "{{ angle + 20 }}°"
          correct: false
        - text: "{{ angle - 20 }}°"
          correct: false

  Angles on a straight line (sum = 180°):

    parameters:
      a: { size: small }
      b: { size: small }
    diagram: 'Angle(A: {{ a }}, B: {{ b }}, size: 180, label_A: "{{ a }}°", label_B: "{{ b }}°")'

  Two angles distinguished by arc count:

    diagram: 'Angle(A: 40, B: 75, arcs_A: 1, arcs_B: 2, label_A: "x", label_B: "y")'

  Right-angle context with an unknown angle:

    parameters:
      a: { size: small }
    diagram: 'Angle(A: {{ a }}, size: 90, label_A: "{{ a }}°")'

  Full revolution showing one reflex angle:

    parameters:
      a:
        type: int
        min: 200
        max: 340
    diagram: 'Angle(A: {{ a }}, size: 360)'


── Line Diagram ─────────────────────────────────────────────

Draws a straight line segment with optional labels at the start
endpoint, end endpoint, and midpoint.

  diagram: 'Line(start: (x1, y1), end: (x2, y2))'

  Coordinates use a standard maths system (y increases upward).

  Parameters:
    start    — start point as (x, y), e.g. start: (-10, 0)
    end      — end point as (x, y), e.g. end: (10, 0)
    label_s  — label at the start endpoint (e.g. "A")
    label_e  — label at the end endpoint (e.g. "B")
    label_m  — label at the midpoint, offset above the line

  Examples:

  Labelled line segment:
    diagram: 'Line(start: (-12, 0), end: (12, 0), label_s: "A", label_e: "B", label_m: "{{ d }} cm")'

  Diagonal line:
    diagram: 'Line(start: (-10, -8), end: (10, 8), label_s: "P", label_e: "Q")'


── Triangle Diagram ─────────────────────────────────────────

Draws a triangle from side lengths and/or an included angle.

  Parameters:
    a, b       — two side lengths (required)
    c          — third side length (optional; see below)
    C          — angle at vertex C in degrees (used to compute c when
                 c is omitted and C is not 90°)
    label_a/b/c — text label shown on each side
    label_A/B/C — text label shown at each angle vertex
    ticks_a/b/c — number of tick marks on each side (1–3)
    arcs_A/B/C  — number of arc indicators at each vertex (1–3)
    label_v    — true shows the numeric value of each side length

  Full three-side triangle with custom labels:

── Parallelogram Diagram ────────────────────────────────────

Draws a parallelogram with a given base and perpendicular height.
A dotted vertical line shows the height with a right-angle marker
at the base, making it clear the height is measured perpendicularly.

Geometric notation is drawn automatically:
  - Single tick marks on the top and bottom edges (equal length b)
  - Double tick marks on the two slanted legs (equal length)
  - Single chevron arrows on top and bottom (parallel pair)
  - Double chevron arrows on the two legs (parallel pair)

  diagram: 'Parallelogram(b: {{ b }}, h: {{ h }}, labels: true)'

  Parameters:
    b         — base length
    h         — perpendicular height
    labels    — true shows numeric values for b and h; false (default) hides them
    label_b   — custom label for the base (overrides labels: true for b)
    label_h   — custom label for the height line (overrides labels: true for h)
    pos       — centre position in the diagram, default (0, 0)
    scale     — scaling factor, default 1

  label_b and label_h accept any string, including {{ }} expressions that have
  already been substituted. Use them when you want units or a custom format:

    diagram: 'Parallelogram(b: {{ b }}, h: {{ h }}, label_b: "{{ b }} cm", label_h: "h = {{ h }}")'

  labels: true is a shorthand that auto-formats both values. Individual label_b
  and label_h always take precedence over labels: true.

  Example:
    parameters:
      b:
        size: medium
      h:
        size: small
      area:
        expr: "b * h"

    diagram: 'Parallelogram(b: {{ b }}, h: {{ h }}, label_b: "{{ b }}", label_h: "h={{ h }}")'

    question:
      text: "Find the area of this parallelogram."
      answer: "{{ area }}"
      solution: "Area = base × height = {{ b }} × {{ h }} = {{ area }}"

  Typical use: area of a parallelogram questions.


── Trapezium Diagram ────────────────────────────────────────

Draws a symmetric (isosceles) trapezium with a given top edge (a),
base (b), and perpendicular height (h). A dotted vertical height line
with a right-angle marker is always drawn inside the shape: when b ≥ a
it drops from the top-left vertex to the base; when a > b it rises from
the bottom-left vertex to the top edge.

Geometric notation is drawn automatically:
  - Single chevron arrow on each parallel side (top and bottom) to
    indicate they are parallel

  diagram: 'Trapezium(a: {{ a }}, b: {{ b }}, h: {{ h }}, labels: true)'

  Parameters:
    a         — length of the top edge
    b         — length of the base (bottom edge)
    h         — perpendicular height
    labels    — true shows numeric values for a, b, and h; false (default) hides them
    label_a   — custom label for the top edge
    label_b   — custom label for the base
    label_h   — custom label for the height line
    pos       — centre position in the diagram, default (0, 0)
    scale     — scaling factor, default 1

  label_a, label_b, and label_h accept any string, including substituted
  {{ }} expressions. Use them when you want units or a custom format:

    diagram: 'Trapezium(a: {{ a }}, b: {{ b }}, h: {{ h }}, label_a: "{{ a }} cm", label_b: "{{ b }} cm", label_h: "h = {{ h }}")'

  Example:
    parameters:
      a:
        size: small
      b:
        size: medium
      h:
        size: small
      area:
        expr: "(a + b) * h / 2"

    diagram: 'Trapezium(a: {{ a }}, b: {{ b }}, h: {{ h }}, label_a: "{{ a }}", label_b: "{{ b }}", label_h: "h={{ h }}")'

    question:
      text: "Find the area of this trapezium."
      answer: "{{ area }}"
      solution: "Area = ½ × (a + b) × h = ½ × ({{ a }} + {{ b }}) × {{ h }} = {{ area }}"

  Typical use: area of a trapezium questions.


── Polygon Diagram ──────────────────────────────────────────

Draws a closed polygon. By default uses equal interior angles so the
shape looks like a regular n-gon with the given side lengths. Supply
angles to draw a geometrically accurate shape. Supply label_angles to
show angle arc markers and labels at each vertex.

Syntax:
  Polygon(sides: [...] [, angles: [...]] [, label_angles: [...]]
          [, labels: true|false] [, name: ""] [, scale: N] [, pos: (x, y)])

Parameters:

  sides        List of side lengths, one per side (minimum 3).
               Optional when angles is given — defaults to all 1.0
               (useful when you only want to show the angle relationships).

  angles       Interior angles in degrees, one per vertex. When provided
               the polygon is drawn with accurate geometry.
               e.g. angles: [60, 120, 60, 120]

  label_angles Text label shown at each vertex, with an arc marker.
               Supply as a bracket list matching the number of vertices.
               Empty entries suppress individual labels.
               A vertex whose angle is ≈ 90° gets a square corner marker
               instead of a curved arc.
               e.g. label_angles: [60°, 120°, 60°, 120°]
               e.g. label_angles: [{{ a }}, ?, {{ a }}, ?]
               e.g. label_angles: [, , ]   ← arcs only, no text

               IMPORTANT: angles[i] is the interior angle AT vertex i.
               label_angles[i] is drawn at the same vertex i. They are
               correctly aligned — do not offset the lists.

  labels       true (default) shows each side length; false hides them.

  name         Optional text shown at the centre of the shape.

  scale        Size multiplier; omit to auto-scale to fit the canvas.

  pos          Centre position in SVG units (default 0, 0).

Examples:

  Angle relationships only (no sides specified):
    diagram: 'Polygon(angles: [60, 120, 60, 120], label_angles: [60°, 120°, 60°, 120°], labels: false)'

  Mixed sides and angles (parallelogram):
    diagram: 'Polygon(sides: [{{ a }}, {{ b }}, {{ a }}, {{ b }}], angles: [{{ ang }}, {{ 180 - ang }}, {{ ang }}, {{ 180 - ang }}], label_angles: [{{ ang }}°, , , ])'

  Right-angled triangle with square corner marker:
    diagram: 'Polygon(sides: [3, 4, 5], angles: [90, 53, 37], label_angles: [, , ])'

  Perimeter question (equal angles, side labels only):
    diagram: 'Polygon(sides: [{{ a }}, {{ b }}, {{ c }}, {{ d }}])'

  Named shape:
    diagram: 'Polygon(sides: [5, 5, 5, 5], name: "ABCD")'

  Typical use: perimeter, area, angle sum questions, identifying
  quadrilateral types by their angles.

── CircleTheorem Diagram ────────────────────────────────────

Draws a labelled circle with named points, chords, radii, arcs,
tangents, angle markers, right-angle markers, and length labels.
Designed for circle-theorem questions (angles in the same segment,
tangent–radius, cyclic quadrilaterals, etc.).

  diagram: 'CircleTheorem(
    points: {O: centre, A: 40, B: 160, C: 260},
    lines: [OA, OB, AB, AC, BC],
    label_angle: {AOB: "2x", ACB: "?"}
  )'

  Parameters:
    radius        — circle radius used only for the viz-scale calculation;
                    the SVG always fills the viewBox (default 5).

    points        — dict of named points. Four value forms are supported:

                    centre             → at the circle centre
                      O: centre

                    <number>           → on the circumference, degrees CCW
                                         from the 3 o'clock position
                      A: 40

                    (x, y)             → explicit SVG coordinates. The origin
                                         is the circle centre; the circle is
                                         always 10 SVG units in radius.
                                         Use for points outside the circle.
                      P: (0, 14)

                    AB CD              → intersection of segment AB and
                                         segment CD. Both segments must be
                                         defined by earlier points in the
                                         same dict.
                      P: AB CD

    lines         — segments to draw, as two-letter pairs. A special
                    'tangentX' token draws a tangent line (red) at the
                    circumference point X, perpendicular to the radius.
                      lines: [OA, OB, AB, tangentT]

    highlight_arc — two circumference-point letters whose minor arc is
                    highlighted in blue.
                      highlight_arc: AB

    label_angle   — dict of angle labels. The key is a three-letter triplet
                    where the middle letter is the vertex; the value is the
                    label string shown near the angle arc.
                      label_angle: {AOB: "2x", ACB: "?"}

    right_angle_at — list of point names where a small right-angle square
                     marker is drawn. The marker is placed between the two
                     line segments that meet at that point (or between the
                     radius and tangent when tangent_at is the same point).
                       right_angle_at: [T]

    label_length  — dict mapping segment names to label strings. The label
                    is placed at the segment midpoint, offset perpendicularly
                    outward from the circle centre.
                      label_length: {OA: "r cm", AB: "?"}

    midpoint      — dict of new named points, each placed at the midpoint
                    of a named segment. The midpoint can then be used in
                    label_length.
                      midpoint: {M: AB}

  Examples:

  Angle at the centre and circumference (same arc):
    diagram: 'CircleTheorem(
      points: {O: centre, A: 40, B: 160, C: 260},
      lines: [OA, OB, AC, BC],
      highlight_arc: AB,
      label_angle: {AOB: "2x", ACB: "x"}
    )'

  Tangent from an external point (tangent–radius right angle):
    diagram: 'CircleTheorem(
      points: {O: centre, A: 140, B: 220, T: 270, P: (0, 14)},
      lines: [PT, PA, PB, OT, tangentT],
      right_angle_at: [T],
      label_length: {PA: "a cm", PB: "b cm", PT: "?"}
    )'

  Chord with midpoint labelled:
    diagram: 'CircleTheorem(
      points: {O: centre, A: 30, B: 150},
      lines: [OA, OB, AB],
      midpoint: {M: AB},
      label_length: {OM: "d cm", AB: "?"}
    )'

  Intersecting chords (PA × PB = PC × PD):
    diagram: 'CircleTheorem(
      points: {O: centre, A: 200, B: 20, C: 110, D: 290, P: AB CD},
      lines: [AB, CD],
      label_length: {PA: "{{ pa }}", PB: "{{ pb }}", PC: "{{ pc }}", PD: "?"}
    )'

  Cyclic quadrilateral (opposite angles sum to 180°):
    diagram: 'CircleTheorem(
      points: {A: 20, B: 100, C: 200, D: 310},
      lines: [AB, BC, CD, DA],
      label_angle: {DAB: "{{ a }}°", BCD: "?"}
    )'

── Cartesian Diagram (Line Graph) ───────────────────────────

Plots a mathematical function on a labelled x-y axis.

  diagram: "Cartesian(xmin: -6, xmax: 6, ymin: -9, ymax: 9, eq: \"{{ m }}*x + {{ b }}\")"

  Parameters:
    xmin, xmax  — horizontal axis range
    ymin, ymax  — vertical axis range
    eq          — the equation to plot in blue (use * for multiplication,
                  ** for powers; x is the variable)
    eq2         — optional second equation plotted in red (same syntax as eq)
    x_label        — optional label shown centred below the x-axis tick numbers
                     (replaces the italic "x" variable label)
    y_label        — optional label shown just above the top of the y-axis
                     (replaces the italic "y" variable label)
    x_tick_labels  — optional comma-separated list of custom labels for the x-axis
                     ticks, replacing the auto-generated numbers. Labels are placed
                     evenly from xmin to xmax. Use xmin: 1 and xmax matching the
                     number of labels so grid lines align with each label.
    points      — optional list of named points drawn as filled blue dots.
                  Syntax: points: ((x1, y1, "Label1"), (x2, y2, "Label2"), ...)
                  The label is optional — omit it or leave it empty for an
                  unlabelled dot.

  Example with axis labels:
    diagram: 'Cartesian(xmin: 0, xmax: 120, ymin: 0, ymax: 50, eq: "5/9*(x-32)", x_label: "Temperature (°F)", y_label: "Temperature (°C)")'

  Example with custom x tick labels (monthly rainfall):
    diagram: 'Cartesian(xmin: 1, xmax: 12, ymin: 0, ymax: 200, eq: "0", x_label: "Month", y_label: "Rainfall (mm)", x_tick_labels: "Jan,Feb,Mar,Apr,May,Jun,Jul,Aug,Sep,Oct,Nov,Dec")'

  Example with two lines (simultaneous equations):
    diagram: 'Cartesian(xmin: -4, xmax: 4, ymin: -4, ymax: 4, eq: "{{ m1 }}*x + 1", eq2: "{{ m2 }}*x - 1")'

  Example with labelled points (distance formula, midpoint):
    diagram: 'Cartesian(xmin: -6, xmax: 6, ymin: -6, ymax: 6, points: (({{ x1 }}, {{ y1 }}, "A"), ({{ x2 }}, {{ y2 }}, "B")))'

  Example combining a line and points (show the y-intercept):
    diagram: 'Cartesian(xmin: -6, xmax: 6, ymin: -9, ymax: 9, eq: "{{ m }}*x + {{ b }}", points: ((0, {{ b }}, "")))'

  Examples:
    Linear:    eq: "{{ m }}*x + {{ b }}"
    Quadratic: eq: "{{ a }}*x**2 + {{ b }}"
    With trig: eq: "sin(x)"

  Use integer or decimal parameters as coefficients — never
  fraction-type parameters (they cannot be substituted into
  the equation string reliably).

  Choose axis ranges so the line or curve is clearly visible:
    For y = mx + b with m in [-4, 4] and b in [-5, 5]:
      xmin: -6, xmax: 6, ymin: -9, ymax: 9

  Labelling the x-axis with strings instead of numbers:

    Use x_tick_labels to replace the auto-generated numeric tick marks with
    custom text. Labels are placed evenly across the x range from xmin to xmax.
    Set xmin: 1 and xmax to the number of labels so each label sits on a whole
    number position and the grid lines align correctly.

    Months of the year:
      diagram: 'Cartesian(xmin: 1, xmax: 12, ymin: 0, ymax: 300, eq: "...",
        x_label: "Month", y_label: "Rainfall (mm)",
        x_tick_labels: "Jan,Feb,Mar,Apr,May,Jun,Jul,Aug,Sep,Oct,Nov,Dec")'

    Days of the week:
      diagram: 'Cartesian(xmin: 1, xmax: 7, ymin: 0, ymax: 100, eq: "...",
        x_tick_labels: "Mon,Tue,Wed,Thu,Fri,Sat,Sun")'

    When x_tick_labels is set:
      - The italic "x" variable label is hidden automatically.
      - Use x_label to add a descriptive axis title below the tick labels.
      - Keep labels short (3–5 characters) to avoid overlapping.

  Ensure the gradient parameter m is never 0 by adding a
  validation rule (see VALIDATION below).


── Parallel Lines Diagram ───────────────────────────────────

Draws two horizontal parallel lines cut by a transversal.
Double-chevron marks on each line indicate they are parallel.

Syntax:
  ParallelLines(angle: N [, arc_1: N, ..., arc_8: N]
                          [, label_1: text, ..., label_8: text]
                          [, labels_angle: [t1, t2, t3, t4, t5, t6, t7, t8]]
                          [, labels: [A, B, C, D, E, F, G, H]]
                          [, colour: name]
                          [, scale: N])

Parameters:

  angle         Transversal angle from horizontal in degrees (1–179).
                e.g. angle: 60

  arc_N         Arc marker for angle region N (0 = none, 1 = single arc,
                2 = double arc). N runs from 1 to 8.
                e.g. arc_1: 1, arc_5: 2

  label_N       Text label for angle region N. Accepts plain text, numbers,
                or {{ expr }} expressions. N runs from 1 to 8.
                e.g. label_1: {{ angle }}, label_5: ?

  labels_angle  Bracket shorthand to set all eight angle labels at once.
                Empty entries leave that label unset.
                e.g. labels_angle: [{{ a }}, , , , {{ b }}, , , ]

  colour        Highlight a set of line segments in golden yellow to
  (or color)    illustrate an angle relationship. Accepted values:
                  cointerior    — co-interior (same-side interior) angles
                  corresponding — corresponding angles
                  alternate     — alternate (Z) angles
                  vert_opposite — vertically opposite angles

  scale         Overall size multiplier (default 1.0).

  labels        Vertex labels for the eight named points on the diagram.
                Supply as a bracket list: labels: [A, B, C, D, E, F, G, H]
                Empty entries hide that label. Labels render in italic.

Angle numbering:

  The transversal creates four angle regions at each intersection.
  Numbering is the same at both intersections (1–4 at the top, 5–8
  at the bottom):

    Top intersection:        Bottom intersection:
        2  |  1                  6  |  5
      ─────+─────              ─────+─────
        3  |  4                  7  |  8

    1/5 = upper-right    2/6 = upper-left
    3/7 = lower-left     4/8 = lower-right

Vertex layout (for the labels parameter):

              A
             /
   B ─────  C  ───── D      (top parallel line)
            /
           /
   E ─────  F  ───── G      (bottom parallel line)
            /
           H

    A = above top intersection (along transversal)
    B = left end of top line       C = top intersection
    D = right end of top line
    E = left end of bottom line    F = bottom intersection
    G = right end of bottom line
    H = below bottom intersection (along transversal)

Examples:

  Basic co-interior question (angles sum to 180°):

    diagram: 'ParallelLines(angle: {{ angle }}, arc_2: 1, arc_6: 1,
              label_2: {{ angle }}, label_6: ?, colour: cointerior)'

  Alternate angles with vertex labels:

    diagram: 'ParallelLines(angle: {{ angle }}, arc_4: 1, arc_6: 1,
              label_4: {{ angle }}, label_6: ?,
              labels: [, , C, , , F, , ], colour: alternate)'

  Corresponding angles:

    diagram: 'ParallelLines(angle: {{ angle }}, arc_1: 1, arc_5: 1,
              label_1: {{ angle }}, label_5: ?, colour: corresponding)'

  Typical parameters block:

    parameters:
      angle:
        type: choice
        values: [40, 55, 65, 70, 75, 80]


── Clock Diagram ────────────────────────────────────────────

  so use a fixed time or generate several separate templates for
  different times.

  Typical use: reading analogue clocks, elapsed time questions.


── Net Diagram ──────────────────────────────────────────────

Draws the unfolded net of a 3D shape. Faces are shown as
flat shapes with a light fill and labelled with key dimensions.

  diagram: 'Net(shape: rect_prism, width: 4, height: 3, depth: 2)'
  diagram: 'Net(shape: cylinder, radius: 3, height: 5)'
  diagram: 'Net(shape: cone, radius: 3, slant: 5)'
  diagram: 'Net(shape: rect_pyramid, width: 4, depth: 4, height: 3)'
  diagram: 'Net(shape: tri_prism, a: 3, b: 4, c: 5, depth: 6)'
  diagram: 'Net(shape: tri_pyramid, a: 5)'

  Parameters:
    shape   — one of: rect_prism | cylinder | cone | rect_pyramid |
                      tri_prism | tri_pyramid
    labels  — true (default) shows dimension labels; false hides them
    show    — comma-separated list of part names to display; omit to
              show the full net (all parts)

  Dimensions by shape:
    rect_prism   — width, height, depth
    cylinder     — radius, height
    cone         — radius, slant  (or radius + height; slant is auto-computed
                   as sqrt(radius²+height²) if omitted or 0)
    rect_pyramid — width, depth, height
    tri_prism    — a, b, c (triangle sides), depth
    tri_pyramid  — a (side length of equilateral tetrahedron)

  Net layouts and part names:
    rect_prism   — cross layout: top/bottom faces above and below the front
                   face, left/right/back faces in a row
                   Parts: top, front, bottom, left, right, back

    cylinder     — rectangle (circumference × height) with circles above
                   and below for the two caps
                   Parts: rect, top, bottom

    cone         — sector for the lateral surface + circle for the base
                   Parts: sector, base

    rect_pyramid — square/rect base in centre, four triangular faces
                   folded outward on each edge
                   Parts: base, front, back, left, right

    tri_prism    — three side rectangles in a row with the two triangular
                   end faces above and below the first rectangle
                   Parts: rect_a, rect_b, rect_c, tri_top, tri_bottom

    tri_pyramid  — four equilateral triangles: one base + three unfolded
                   faces (reflects each face outward from base)
                   Parts: base, face_a, face_b, face_c

  Note: dimension labels are associated with their part — hiding a part
  also hides its label.

  Examples:

  Rectangular prism net:
    diagram: 'Net(shape: rect_prism, width: {{ w }}, height: {{ h }}, depth: {{ d }})'

  Cylinder net (full):
    diagram: 'Net(shape: cylinder, radius: {{ r }}, height: {{ h }})'

  Cylinder net — rectangle and one circle only:
    diagram: 'Net(shape: cylinder, radius: {{ r }}, height: {{ h }}, show: rect,bottom)'

  Cylinder net — single circle only (e.g. to identify the cap shape):
    diagram: 'Net(shape: cylinder, radius: {{ r }}, height: {{ h }}, show: top)'

  Cone net (slant given):
    diagram: 'Net(shape: cone, radius: {{ r }}, slant: {{ l }})'

  Cone net (height given, slant auto-computed):
    diagram: 'Net(shape: cone, radius: {{ r }}, height: {{ h }})'

  Rectangular pyramid net:
    diagram: 'Net(shape: rect_pyramid, width: {{ w }}, depth: {{ d }}, height: {{ h }})'

  Rectangular pyramid — base and two faces only:
    diagram: 'Net(shape: rect_pyramid, width: {{ w }}, depth: {{ d }}, height: {{ h }}, show: base,front,back)'

  Triangular prism net:
    diagram: 'Net(shape: tri_prism, a: {{ a }}, b: {{ b }}, c: {{ c }}, depth: {{ dep }})'

  Equilateral tetrahedron net:
    diagram: 'Net(shape: tri_pyramid, a: {{ a }})'


── CompositeSolid Diagram ───────────────────────────────────

Draws a 3D composite solid made from two or more primitive shapes
stacked together. Shapes are rendered with an oblique projection
and painter's-algorithm depth sorting, giving a clear sense of
the overall 3D structure.

  diagram: 'CompositeSolid(rect_prism(w:4, h:2, d:3), half_cylinder(r:1.5, length:4, on:top))'

  Syntax:
    CompositeSolid(<shape1>, <shape2>, ...)

  Each shape primitive is written as a function call with named
  keyword arguments:

  ── Shape Primitives ─────────────────────────────────────────

  rect_prism(w, h, d)
    Rectangular prism (cuboid).
      w   — width  (x-axis)
      h   — height (y-axis)
      d   — depth  (z-axis)

  half_cylinder(r, length, axis)
    Upper half-cylinder with a flat face at the bottom.
      r       — radius of the circular cross-section
      length  — length along the chosen axis
      axis    — x (default) or z

  cylinder(r, h)
    Full cylinder standing upright.
      r   — radius
      h   — height

  cone(r, h)
    Cone with its base at the bottom.
      r   — base radius
      h   — height

  ── Positioning ──────────────────────────────────────────────

  on: top | front | right
    Stacks the shape relative to the accumulated bounding box
    of all previously placed shapes.
      on: top    — place on top of the current composite
      on: front  — place in front of the current composite
      on: right  — place to the right of the current composite
    The shape is centred on the chosen face automatically.

  at: x,y,z
    Place the shape at an absolute position in the scene
    (overrides on:).

  ── Other Parameters ─────────────────────────────────────────

  labels
    true (default) shows dimension labels on rect_prism edges;
    false hides all labels.

  Examples:

  Rectangular prism with a half-cylinder on top (e.g. a shed):
    diagram: 'CompositeSolid(rect_prism(w:{{ w }}, h:{{ h }}, d:{{ d }}), half_cylinder(r:{{ r }}, length:{{ w }}, on:top))'

  Rectangular prism with a cone on top (e.g. a tower):
    diagram: 'CompositeSolid(rect_prism(w:{{ w }}, h:{{ h }}, d:{{ w }}), cone(r:{{ r }}, h:{{ ch }}, on:top))'

  Rectangular prism with a cylinder on top (e.g. a silo):
    diagram: 'CompositeSolid(rect_prism(w:{{ w }}, h:{{ h }}, d:{{ w }}), cylinder(r:{{ r }}, h:{{ ch }}, on:top))'

  Two rectangular prisms side by side:
    diagram: 'CompositeSolid(rect_prism(w:{{ w1 }}, h:{{ h1 }}, d:{{ d }}), rect_prism(w:{{ w2 }}, h:{{ h2 }}, d:{{ d }}, on:right))'

  Three-part composite (base + body + roof):
    diagram: 'CompositeSolid(rect_prism(w:6, h:1, d:4), rect_prism(w:4, h:3, d:3, on:top), half_cylinder(r:1.5, length:4, on:top))'


── Solid3D Diagram ───────────────────────────────────────────

Draws a fully annotatable 3D solid using oblique projection,
viewed from above-left. Supports named points, annotation lines,
length labels, angle markers, and right-angle markers.

  diagram: 'Solid3D(shape: rect_prism, w: 4, h: 3, d: 5)'
  diagram: 'Solid3D(shape: square_pyramid, w: 4, h: 5, d: 4)'
  diagram: 'Solid3D(shape: triangular_prism, w: 3, h: 4, d: 6)'

  ── Shape and Dimensions ────────────────────────────────────

  shape   — solid type (default: rect_prism):
              rect_prism        rectangular prism (cuboid)
              square_pyramid    square-based pyramid
              triangular_prism  triangular prism
  w       — width  (x-axis)
  h       — height (y-axis)
  d       — depth  (z-axis)

  ── Built-in Vertex Names ───────────────────────────────────

  rect_prism
    Bottom face:  A (front-left)  B (front-right)
                  C (back-right)  D (back-left)
    Top face:     E (front-left)  F (front-right)
                  G (back-right)  H (back-left)

  square_pyramid
    Base:  A (front-left)  B (front-right)
           C (back-right)  D (back-left)
    Apex:  P

  triangular_prism
    Front face:  A (bottom-left)  B (bottom-right)  C (top)
    Back face:   D (bottom-left)  E (bottom-right)  F (top)

  ── Named Points ────────────────────────────────────────────

  points: {NAME: VALUE, ...}

  Adds extra named points beyond the built-in vertices.
  Value forms:
    (x, y, z)      unit-cube coordinates (0–1 on each axis,
                   scaled by w/h/d at render time)
    centre_base    centre of the bottom face: (0.5, 0, 0.5)
    centre_top     centre of the top face: (0.5, 1, 0.5)
    midpoint(AB)   midpoint of segment AB
    foot(P, base)  point on y=0 directly below P

  ── Annotation Lines ────────────────────────────────────────

  lines: [AC, BG, ...]
    Solid black lines drawn between named points.

  dash: [AG, DF, ...]
    Dashed grey lines drawn between named points.

  highlight: [AC, BF]
    Lines drawn in blue (default). To specify a colour per segment:
    highlight: [(AC, blue), (BF, red)]
    Any CSS colour name or hex code is accepted.

  ── Labels ──────────────────────────────────────────────────

  label_length: {AB: "{{ w }} cm", BF: "{{ h }}", AG}
    Draws a length label beside a segment, placed outside the
    shape. Provide an explicit string value, or omit the value
    (bare segment name) to have the length computed automatically
    from the shape dimensions (shown as an integer or 2 d.p.).

  label_point: {A: "A", P: "P"}
    Draws a filled dot and text label at a named point.
    Labels are positioned outside the shape and avoid lines.

  label_angle: {ABF: "θ", DAB: "90°"}
    Draws an angle arc and label. Each key is a three-letter triplet
    where the middle letter is the vertex; the outer letters are the
    two ray endpoints. The value is the label string shown near the arc.
    Multiple angles can be specified in the same dict.

  right_angle_at: {A: [AB, AE]}
    Draws a small square right-angle marker at vertex A between
    the two named segments.

  Examples:

  Rectangular prism with auto-computed edge labels:
    diagram: 'Solid3D(shape: rect_prism, w: {{ w }}, h: {{ h }}, d: {{ d }},
      label_length: {AB, AE, AD})'

  Pyramid showing slant height from apex to base midpoint:
    diagram: 'Solid3D(shape: square_pyramid, w: {{ b }}, h: {{ h }}, d: {{ b }},
      points: {M: midpoint(AB)},
      lines: [PM],
      label_length: {AB: "{{ b }}", PM: "l"},
      label_point: {A: "A", B: "B", P: "P"})'

  Triangular prism with highlighted hypotenuse:
    diagram: 'Solid3D(shape: triangular_prism, w: {{ a }}, h: {{ b }}, d: {{ d }},
      highlight: [(AC, blue)],
      label_length: {AB, BC, AC, AD},
      label_point: {A: "A", B: "B", C: "C", D: "D"})'

  Rectangular prism with space diagonal:
    diagram: 'Solid3D(shape: rect_prism, w: {{ w }}, h: {{ h }}, d: {{ d }},
      lines: [AG],
      dash: [BG, AB],
      label_length: {AG: "d", AB, AE, AD},
      label_point: {A: "A", G: "G"})'

── Fraction Bar Diagram ─────────────────────────────────────

Draws two equal-width horizontal fraction bars stacked vertically.
The top bar is subdivided by the denominator of the first fraction
and its numerator cells are highlighted in blue. The bottom bar does
the same for the second fraction. Useful for showing equivalent
fractions side by side.

  diagram: "FractionBar(a: 2/3, b: 4/6, label: true)"
  diagram: "FractionBar(a: 2/3, den: 12, label: true)"

  Parameters:
    a       — the first fraction (top bar); accepts n/d, \frac{n}{d}, or a
              fraction parameter e.g. {{ p }}/{{ q }}
    b       — the second fraction (bottom bar); use this OR den, not both
    den     — target denominator for the bottom bar; the equivalent
              numerator is calculated automatically
              e.g. a: 2/3, den: 12  →  bottom bar shows 8/12
    label     — true (default) shows the fraction above the top bar and
                below the bottom bar; false hides both labels
    label_den — false (default); when true writes the denominator of each
                bar to the right of that bar (e.g. "3", "12")

  Examples:
    Explicit second fraction:
      diagram: "FractionBar(a: 2/3, b: 4/6)"

    Auto-calculated equivalent fraction:
      diagram: "FractionBar(a: {{ p }}/{{ q }}, den: {{ d }})"

    Without labels:
      diagram: "FractionBar(a: 3/4, b: 6/8, label: false)"

    Denominator labels to the right of each bar:
      diagram: "FractionBar(a: 2/3, den: 12, label_den: true)"

  Typical use: fraction equivalence, comparing fractions,
  introducing equivalent fractions in Stage 4.

── Balls Diagram ────────────────────────────────────────────

── Tree Diagram ─────────────────────────────────────────────

Draws a probability tree diagram. Each level represents one stage
of a multi-stage experiment. Branches are labelled with outcome
names and optionally their probabilities; leaf nodes optionally
show the combined path probability.

Syntax:

  diagram: 'TreeDiagram(
    stages: ["Draw 1", "Draw 2"],
    branches: [["Red", "Red"], ["Red", "Green"], ["Green", "Red"], ["Green", "Green"]],
    probs: [["2/7", "1/6"], ["2/7", "5/6"], ["5/7", "2/6"], ["5/7", "5/6"]],
    end_labels: ["2/42", "10/42", "10/42", "25/42"],
    highlight: [3]
  )'

Parameters:

  branches    Required. A list of root-to-leaf paths. Each path is a
              list of outcome label strings, one per stage.
              Paths with a shared prefix automatically share the
              same node: [["Red","Red"],["Red","Green"]] draws one
              "Red" node at stage 1 with two children.

  stages      Optional. Column header labels, one per level.
              Displayed in bold above the corresponding node column.

  probs       Optional. Same shape as branches. The probability
              label placed on each branch segment. Accepts plain
              fractions (2/7), decimals (0.286), or LaTeX fraction
              strings (\frac{2}{7}).

  end_labels  Optional. One label per path, shown to the right of
              each leaf node. Same format as probs.

  highlight   Optional. A list of 0-based path indices to emphasise.
              Highlighted paths render in accent blue; all others
              render in muted grey. Omit to render all paths at
              full default styling.

  pos         Optional centre-offset position, default (0, 0).

Highlight behaviour:
  When highlight is set, non-highlighted branches and labels render
  in grey (#9ca3af). Highlighted branch lines are thicker and
  drawn in blue (#2563eb). Highlighted end labels also appear in
  blue.

{{ }} substitution:
  All string values in stages, branches, probs, and end_labels
  support {{ }} template substitution.

  Example (marble bag without replacement):

    parameters:
      g:
        min: 3
        max: 6
      total:
        min: 7
        max: 10

    diagram: 'TreeDiagram(
      stages: ["Draw 1", "Draw 2"],
      branches: [["Green", "Green"], ["Green", "Other"],
                 ["Other", "Green"], ["Other", "Other"]],
      probs: [["{{ g }}/{{ total }}", "{{ g - 1 }}/{{ total - 1 }}"],
              ["{{ g }}/{{ total }}", "{{ total - g }}/{{ total - 1 }}"],
              ["{{ total - g }}/{{ total }}", "{{ g }}/{{ total - 1 }}"],
              ["{{ total - g }}/{{ total }}", "{{ total - g - 1 }}/{{ total - 1 }}"]],
      highlight: [0]
    )'

Examples:

  Simple coin-flip tree (2 stages, no labels):
    diagram: 'TreeDiagram(
      branches: [["H", "H"], ["H", "T"], ["T", "H"], ["T", "T"]]
    )'

  Two-stage marble bag with highlight on the Green → Green path:
    diagram: 'TreeDiagram(
      stages: ["Draw 1", "Draw 2"],
      branches: [["Red", "Red"], ["Red", "Green"], ["Green", "Red"], ["Green", "Green"]],
      probs: [["2/7", "1/6"], ["2/7", "5/6"], ["5/7", "2/6"], ["5/7", "5/6"]],
      end_labels: ["2/42", "10/42", "10/42", "25/42"],
      highlight: [3]
    )'

  Typical use: multi-stage probability, dependent and independent
  events, listing outcomes of a two-stage experiment.

── Box Plot Diagram ─────────────────────────────────────────

Draws a horizontal box-and-whisker plot for one or two datasets.
Each box shows the five-number summary: minimum, Q1, median,
Q3, and maximum. The IQR box is shaded; whisker ends are capped.
Quartiles use the exclusive method (same as quartile() in
expressions). Two datasets are stacked vertically on a shared
axis and colour-coded blue/red.

Single dataset:
  diagram: "BoxPlot(data: [3, 7, 8, 9, 11, 13, 15])"

With a label:
  diagram: 'BoxPlot(data: [{{ data }}], label: "Class A")'

Two datasets:
  diagram: 'BoxPlot(data: [{{ data1 }}], label: "Class A", data2: [{{ data2 }}], label2: "Class B")'

  Parameters:
    data    — list of numeric values for the first dataset (required)
    label   — optional row label for the first dataset
    data2   — list of numeric values for the second dataset (optional)
    label2  — optional row label for the second dataset

  The axis is auto-scaled to the combined data range.
  Axis ticks are placed at the five-number summary values.

  Typical use: comparing distributions, identifying skew,
  reading off quartiles and range.


── AlgebraTable Diagram ─────────────────────────────────────

Renders a two-row table: the top row shows x values and the
bottom row shows the output of an algebraic expression for
each x. One or more output cells can be left blank for the
student to complete interactively.

Basic syntax (single blank cell):

  diagram: 'AlgebraTable(x_min: 1, x_max: 7, expr: "x+2", blank: 4)'

This displays x values 1–7 with outputs computed from x+2.
The output cell for x=4 is highlighted in yellow and left
blank for the student to fill in.

  Parameters:
    x_min    — first x value (integer)
    x_max    — last x value (integer)
    step     — increment between x values (default 1)
               Use step: 10 for values like 10, 20, 30, 40, 50
    expr     — algebraic expression using x as the variable
               Supports: +, -, *, /, ** and implicit multiplication
               e.g. "x+2", "2x+5", "3x-1", "x**2"
               Parameters can be substituted: "{{a}}x+{{b}}"
    blank    — the x value whose output cell is left blank (single blank)
    label_1  — label for the top row (default: x)
    label_2  — label for the bottom row (default: the expression)

  Example — table for y = 3x + 1, asking for the value at x=5:

    parameters:
      a:
        type: choice
        values: [3, 4, 5]

    question:
      text: "Complete the table for $y = 3x + 1$."
      answer: "{{ 3 * a + 1 }}"
      answer_format: integer
      solution: "When $x = {{ a }}$: $3 \\times {{ a }} + 1 = {{ 3 * a + 1 }}$"

    diagram: 'AlgebraTable(x_min: 1, x_max: 6, expr: "3x+1", blank: {{ a }})'


  Example — scones question with custom row labels and step:

    diagram: 'AlgebraTable(x_min: 10, x_max: 50, step: 10, expr: "2x+150",
              label_1: "Scones", label_2: "Temperature")'

    Produces columns for 10, 20, 30, 40, 50 with labelled rows.


── AlgebraTable — Multi-step blanks ────────────────────────

When multiple output cells should be blank simultaneously, use
the blanks parameter with a comma-separated list of x values.
The student fills them in one at a time — the highlighted
(yellow) cell advances automatically when each answer is
correct. Previously answered cells show their value.

  diagram: 'AlgebraTable(x_min: 1, x_max: 7, expr: "x+2", blanks: "3,4,5")'

  Parameters (in addition to the basic ones above):
    blanks    — comma-separated x values to leave blank, e.g. "3,4,5"
    highlight — which blank is currently active (yellow); defaults to
                the first value in blanks — omit this in templates

  The answers block is NOT needed for multi-step AlgebraTable —
  the engine computes the correct answer for each blank directly
  from the expression.

  The solution field IS used: it is rendered separately for each
  blank, with blank_x set to the x value being answered. This
  lets you show working for each step.

  Full multi-step example:

    parameters:
      a:
        type: choice
        values: [2, 3, 4]
      b:
        type: choice
        values: [1, 2, 3, 5]

    question:
      text: "Complete the table for $y = {{ a }}x + {{ b }}$."
      solution: "When $x = {{ blank_x }}$: ${{ a }} \\times {{ blank_x }} + {{ b }} = {{ a * blank_x + b }}$"

    diagram: 'AlgebraTable(x_min: 1, x_max: 6, expr: "{{a}}x+{{b}}", blanks: "2,4,6")'

  Note: blank_x is a special variable available only inside the
  solution field of a multi-step template. It automatically takes
  the value of the x column being answered at each step.

  The student sees:
    • "I don't know" button — reveals the answer for the current
      cell and flags the question for tutor review.
    • On incorrect answer — the solution for that cell is shown.
    • Table fills in left to right as each blank is answered.


── Data Table Diagram ───────────────────────────────────────

Renders a static data table with a grey header row and white
data rows. Useful for presenting sets of values to students —
reading-off questions, statistics, unit conversion tables, etc.

  diagram: 'DataTable(headers: [Month, Rainfall], rows: [(Jan, 45), (Feb, 62), (Mar, 38)])'

  Parameters:
    headers   — comma-separated column heading strings in [ ]
    rows      — list of data rows, each a (val, val, ...) tuple
    label_col — false (default) | true: also shades the first
                column grey, making it act as a row-header column
    highlight — optional list of row tokens to shade in accent blue.
                Token format: "row_N" where N is 1-based (row_1 =
                first data row, row_2 = second data row, etc.).
                The header row cannot be highlighted.
                Single row:    highlight: ["row_1"]
                Multiple rows: highlight: ["row_1", "row_3"]
                Omit or leave empty for no highlight.

  Column layout mirrors AlgebraTable: the first column is 1.5×
  the width of each data column so label text (e.g. "January")
  has room to breathe.

  Supports {{ }} substitution in any cell value:
    rows: [(Jan, {{ r1 }}), (Feb, {{ r2 }}), (Mar, {{ r3 }})]

  Example — monthly rainfall reading question:

    parameters:
      r1: { min: 20, max: 120 }
      r2: { min: 20, max: 120 }
      r3: { min: 20, max: 120 }

    diagram: 'DataTable(headers: [Month, Rainfall (mm)], rows: [(Jan, {{ r1 }}), (Feb, {{ r2 }}), (Mar, {{ r3 }})])'

    question:
      text: "Which month had the highest rainfall?"
      answers:
        - text: "January"
          correct: "r1 > r2 and r1 > r3"
        - text: "February"
          correct: "r2 > r1 and r2 > r3"
        - text: "March"
          correct: "r3 > r1 and r3 > r2"

  Example — two-column table with label_col:

    diagram: 'DataTable(headers: [Shape, Area formula], rows: [(Square, s^2), (Rectangle, l × w), (Triangle, ½bh)], label_col: true)'

  Example — two-way frequency table with highlighted row (row_1 = "Does A"):

    diagram: 'DataTable(
        headers:   [, Does {{ label_B }}, Does not {{ label_B }}, Total],
        rows: [
          (Does {{ label_A }},     {{ both }},    {{ a_only }}, {{ does_A }}),
          (Does not {{ label_A }}, {{ b_only }},  {{ neither }}, {{ not_A }}),
          (Total,                  {{ does_B }},  {{ not_B }},  {{ grand_total }})
        ],
        label_col:  true,
        highlight:  ["row_1"]
      )'

  The highlighted row renders in accent blue (#dbeafe for data cells,
  #bfdbfe for the label-column cell). All other rows are unaffected.

  Typical use: reading tables, statistics questions, data
  interpretation, two-way frequency tables, unit conversion references.


── Venn Diagram ─────────────────────────────────────────────

Draws a two-circle Venn diagram inside a rounded rectangle
representing the universal set. Each region (only A, both,
only B, neither) shows an optional count. One region can be
highlighted in blue for emphasis.

Syntax:

  diagram: 'VennDiagram(
    label_A: "Sport", label_B: "Music",
    only_A: 12, both: 5, only_B: 8, neither: 3,
    total: 28,
    highlight: "both",
    show_labels: true,
    label_box: "Students"
  )'

Parameters:

  label_A     Label for circle A (left). Displayed inside the
              circle near the top. Default: "A".

  label_B     Label for circle B (right). Default: "B".

  only_A      Count shown in the left crescent (A but not B).

  both        Count shown in the lens-shaped overlap (A and B).

  only_B      Count shown in the right crescent (B but not A).

  neither     Count shown in the bottom-right corner of the
              rectangle (outside both circles).

  total       Optional. If provided and does not equal
              only_A + both + only_B + neither, a small ⚠ badge
              is shown to flag the mismatch.

  highlight   Optional. A single value or a list of values to shade
              in accent blue. Multiple values let you highlight a
              union or any combination of regions.
              Accepted values:
                "only_A"   — left crescent
                "only_B"   — right crescent
                "both"     — overlap lens
                "neither"  — outside both circles
                "A"        — entire circle A (crescent + lens)
                "B"        — entire circle B (crescent + lens)

              Single region:   highlight: "both"
              Union A ∪ B:     highlight: ["only_A", "both", "only_B"]
              Omit for no highlight.

  show_labels false (default): show count values only.
              true: also show a small label below each count
              ("Sport only", "Both", "Neither", etc.).

  label_box   Optional text placed in the top-left corner of
              the bounding rectangle (e.g. the universal set
              name such as "Students" or "ξ").

  pos         Optional centre-offset position, default (0, 0).

{{ }} substitution:
  All numeric values (only_A, both, only_B, neither, total)
  support {{ }} template substitution.

Example — class survey:

  parameters:
    a: { min: 5, max: 15 }
    b: { min: 3, max: 10 }
    c: { min: 4, max: 12 }
    d: { min: 1, max: 6 }

  diagram: 'VennDiagram(
    label_A: "Sport", label_B: "Music",
    only_A: {{ a }}, both: {{ b }}, only_B: {{ c }}, neither: {{ d }},
    total: {{ a + b + c + d }},
    label_box: "Students"
  )'

  question:
    text: "How many students play sport?"
    answer: "{{ a + b }}"
    answer_format: integer

Example — with highlight on the overlap:

  diagram: 'VennDiagram(
    label_A: "Swimmers", label_B: "Runners",
    only_A: 8, both: 3, only_B: 11, neither: 2,
    highlight: "both", show_labels: true
  )'

  Typical use: two-way sorting, set notation, Venn-diagram
  reading questions, intersection / union problems.


── Combining Multiple Diagrams ─────────────────────────────

Multiple diagram calls can be combined in a single diagram field by separating
them with a semicolon (;). Each part is rendered onto the same SVG canvas.
Use the pos parameter to position each shape so they do not overlap.

IMPORTANT: Always use semicolon (;) to separate multiple diagrams — do NOT use
the YAML block scalar (|) as it causes rendering issues.

The coordinate system is centred at (0, 0). Positive x moves right; positive y
moves down (SVG convention). A typical canvas spans roughly -30 to +30 in x and
-15 to +15 in y.

  Example — two rectangles side by side for a size comparison question:

    diagram: 'Rect(x: 10, y: 11.9, pos: (-10, 0), labels: false, name: "Vic"); Rect(x: 10, y: 3.4, pos: (10, 0), labels: false, name: "Tas")'

  Positioning tips:
    - Separate shapes horizontally: each shape's pos x should be offset by at
      least half the sum of their widths plus a small gap (e.g. 2 units).
    - Centre the overall composition at x=0 so it fills the canvas evenly.
    - Use the name parameter on Rect to label each shape from inside it.
    - Scale raw parameter values down to SVG units (canvas ≈ ±30 x, ±15 y).
      e.g. if vic_height: 238, use 238/20 = 11.9 in the diagram string.

  Note: the viewBox is taken from the last diagram entry, so for multi-diagram
  layouts the default viewBox (-30 -15 60 30) applies. Scale shapes accordingly.

── Question types: Multipart and multiple choice ──────────────────────────────────────────

  parameters:
    a:
      type: fraction
      size: small
      proper: true
    is_term:
      expr: denominator(a) % 2 == 0 or denominator(a) % 5 == 0
    ans:
      expr: '"Yes" if is_term else "No"'

  question:
    text: "Consider the fraction {{ a | fraction }}."
    parts:
      - text: "Write {{ a | fraction }} as a decimal."
        answer: "{{ a | decimal }}"
        solution: "{{ a | fraction }} = {{ a | decimal }}"
      - text: "Is {{ a | fraction }} a terminating decimal?"
        choices:
          - text: "Yes"
            correct: is_term
          - text: "No"
            correct: not is_term
        solution: "{{ ans }}, because the denominator {{ 'has' if is_term else 'does not have' }} only factors of 2 and 5."



── Code: Conditional Text ──────────────────────────────────────────

    parameters:
      right_angle:
        type: bool

    question:
      text: "Is a triangle {{ 'with' if right_angle else 'without'}} a 90° angle a right-angle triangle?"
      answers:
        - text: "Yes"
          correct: "right_angle"
        - text: "No"
          correct: "not right_angle"
      solution: "A triangle {{ 'with' if right_angle else 'without'}} a 90° angle is {{ '' if right_angle else 'not '}}a right-angle triangle."

── Code: For-Loop Table ──────────────────────────────────────────

    Use {% for var in list %}...{% endfor %} to repeat a block for every item in a
    list parameter. This is most useful for building Markdown tables from data points.

    Syntax:

        {% for var in list_param %}
        ...{{ var[0] }}...{{ var[1] }}...
        {% endfor %}

    - var[0], var[1], etc. access elements of each item by index.
    - The list parameter must use type: literal with a value: containing a list.

    Example — data table from a list of (x, y) pairs:

        parameters:
          x_label:
            type: literal
            value: "Hours studied"
          y_label:
            type: literal
            value: "Test score (%)"
          points:
            type: literal
            value: [[1,45],[2,55],[3,62],[4,70],[5,78]]

        question:
          text: |
            | {{ x_label }} | {{ y_label }} |
            |---|---|
            {% for p in points %}| {{ p[0] }} | {{ p[1] }} |
            {% endfor %}

    Important: use | (literal block scalar) rather than > (folded) for the
    question text field when it contains {% %} tags, so that newlines are
    preserved. If > is used accidentally, the system will attempt to correct it
    automatically, but | is always the safe choice.


── Input boxes: Equation input box for indices ──────────────────────────────────────────

Example — index notation (equation entry widget):

  parameters:
    base: {min: 2, max: 4}
    exp:  {min: 2, max: 4}
    ans:  "{{ base ** exp }}"

  question:
    text: "Write ${{ ans }}$ as an index."
    answer: "{{ ans }}"
    answer_format: equation
    solution: "{{ base }}^{{ exp }} = {{ ans }}"

KNOWLEDGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Knowledge item is a reusable explanation — a formula, rule,
or definition — that can be attached to one or more Skills and
displayed alongside a question or its solution.

── Creating a Knowledge Item ────────────────────────────────

1. Navigate to the Knowledge list (Knowledge in the main menu).
2. Click "+ New".
3. Fill in the fields on the left; a live preview appears on
   the right as you type.

Fields:

  Title (required)
    The name of the concept shown as a heading in the preview.
    e.g. "Circumference of a Circle"

  Text
    The main explanation or formula. Supports LaTeX:
      $...$    inline maths,  e.g. $C = 2\pi r$
      $$...$$  display maths, e.g. $$A = \pi r^2$$
    Use **bold** for emphasis. Plain text is also fine.

  Diagram
    An optional diagram using the same syntax as template
    diagrams (see the DIAGRAMS section above).
    e.g. Circle(radius: 5, label_r: true, label_d: true)
    Leave blank if no diagram is needed.

  Text 2
    A second block of text shown below the diagram. Use this
    for a worked example, a second formula, or additional notes.
    Supports the same LaTeX syntax as Text.

4. Click Save. The item is created and its URL updates to
   /knowledge/<id> so you can bookmark or share it.

── Linking to Skills ─────────────────────────────────────────

To associate a Knowledge item with a Skill, open the item
from the Knowledge list, find the skill by its ID, and add it
to skill_ids. Once linked, the Knowledge item is automatically
shown alongside the solution whenever a student answers a
question from that skill.

── Generating from an Image ──────────────────────────────────

When creating a new item you can pre-fill all fields from a
screenshot or photo of a textbook, whiteboard, or worked example:

1. Click "📷 From Image" in the toolbar.
2. Upload an image by clicking the drop zone, dragging a file
   onto it, or pasting from the clipboard (Ctrl+V / Cmd+V).
3. Optionally type extra instructions in the text box below
   the image (e.g. "Focus on the formula, not the example").
4. Click "Generate Knowledge".

The AI fills in Title, Text, Diagram and Text 2 from the image.
Review and edit the fields before saving.

── Using a Knowledge Item in a Template ─────────────────────

To add information to a question use knowledge. This can be
placed in the question, the solution or below the answer. If
added to the solution, the information only shows if the
student answers incorrectly.

post_answer: '{{ Knowledge("Multiplying and Dividing Positives and Negatives") }}'
